Generic communication transport abstraction.

Provides driver-independent packet communication over Serial, TCP, UDP, and CAN interfaces.

  • tcp port

int
Return values
0Initialization successful
-1Initialization failed

Initialize transport layer.

Interface selection via cmds->interface string:

  • "serial" — opens cmds->ip as a serial port at 115200 baud.
  • "tcp" — connects TCP to cmds->ip : cmds->port.
  • "udp" — opens a UDP socket aimed at cmds->ip : cmds->port. Uses the same frame format as TCP (CRC16-CCITT appended).
  • "can" — opens cmds->ip as a serial port at 115200 baud. Uses the same drv_serial driver as "serial" because the USB-CAN adapter appears as a virtual COM port. Only the frame packing differs.
Parameters
cmdsParsed command-line arguments.
Returns
0 on success, -1 on failure.

int transport_receive ( comm_packet_t *  pkt,
int32_t *  thread_running_flag 
)

Receive a communication packet from the active transport.

This function implements a byte-wise state machine parser that reconstructs a packet from the transport stream.

Expected frame format:

-----------------------------------------------------------
| ':' | CMD | LEN_H | LEN_L | DATA ... | CRC_H | CRC_L |
-----------------------------------------------------------

The function validates the CRC before returning the packet.

The parser operates continuously while the thread running flag remains set.

Parameters
[out]pktPointer to packet structure where received data will be stored.
[in]thread_running_flagPointer to thread control flag. Reception continues while this value is non-zero.
Returns
int
Return values
>0Payload length of the received packet
-1Invalid argument or thread stopped
-3Payload length exceeds buffer size
-5CRC verification failed

Receive a communication packet from the active transport.

Spins until a complete valid packet arrives or the thread stop flag is cleared.

Serial / TCP / UDP parser (7 states)
Reconstructs packets from the byte stream and validates CRC16. For UDP each drv_udp_rx() call returns one complete datagram; the byte-wise parser then processes the bytes within that datagram in the same way as the Serial and TCP paths. State is preserved in module-level variables across calls.
CAN parser (4 states)
Parses the compact CAN frame:
State 0 : scan for ':' start delimiter (re-sync on noise/misalign)
State 1 : read CMD byte → pkt->command
State 2 : read LEN byte → pkt->length (validated ≤ CAN_MAX_PAYLOAD)
State 3 : read LEN data bytes → pkt->data[]

int transport_send ( comm_packet_t *  pkt)

Send a communication packet through the active transport.

The packet is encoded into the following frame format before transmission:

-----------------------------------------------------------
| ':' | CMD | LEN_H | LEN_L | DATA ... | CRC_H | CRC_L |
-----------------------------------------------------------
1B 1B 1B 1B N B 1B 1B

Where:

  • ':' : Start delimiter
  • CMD : Command identifier
  • LEN_H/LEN_L : Payload length (big endian)
  • DATA : Payload bytes
  • CRC : CRC16-CCITT calculated over CMD + LEN + DATA

The function automatically routes the frame to the active driver (Serial, TCP, or UDP).

Parameters
[in]pktPointer to communication packet structure.
Returns
int
Return values
>0Number of bytes transmitted
-1Invalid packet or driver not initialized

Send a communication packet through the active transport.

Serial / TCP / UDP path
':' | CMD(1B) | LEN_H(1B) | LEN_L(1B) | DATA(NB) | CRC_H(1B) | CRC_L(1B)
CRC16-CCITT appended over CMD + LEN_H + LEN_L + DATA. For UDP, the complete framed packet is delivered as a single datagram.
CAN path
':' | CMD(1B) | LEN(1B) | DATA[0..LEN-1]
  • CMD : pkt->command (maps to the 11-bit CAN ID, low 8 bits)
  • LEN : pkt->length (single byte, 0–8, no LEN_H byte)
  • DATA: pkt->data[] (raw payload, no CRC bytes appended)
Parameters
pktPacket to transmit.
Returns
Bytes written (> 0) on success, -1 on error.

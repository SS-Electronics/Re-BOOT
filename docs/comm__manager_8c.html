Detailed Description

Communication receive thread for the Re-BOOT host application.

This module owns the dedicated RX thread that runs for the entire lifetime of a firmware update session. Its only job is to call transport_receive() in a tight loop, heap-allocate a copy of each successfully parsed packet, and push that copy into the shared handle_queue_receive_packets queue for the FSM signal generator to consume.

Memory ownership
Each packet pushed into the queue is a malloc'd comm_packet_t. Ownership transfers to the queue consumer (act_fsm_signal_generation) which is responsible for calling free() after processing.
Error handling
transport_receive() returns negative values for framing errors (-3) and CRC mismatches (-5). Both are logged here with the raw return code so that serial line problems become visible during debugging. The thread simply loops back and waits for the next valid frame — no further action is needed because the host protocol is stop-and-wait and the target will retransmit on timeout.

◆ receive_info_packet

comm_packet_t receive_info_packet
static

Temporary stack packet used during reception.

transport_receive() writes the parsed packet into this stack variable. A heap copy is made before the packet is queued so that the next call to transport_receive() cannot overwrite a packet that is still being processed by the FSM thread.

This variable is not shared between calls (it is re-used each iteration) and is not accessed by any other thread, so no synchronisation is needed for the variable itself.

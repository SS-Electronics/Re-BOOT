Detailed Description

State object definitions and transition table for the Re-BOOT firmware update FSM.

This file has two responsibilities:

  1. State objects — one fsm_state_t per logical state with no entry/exit callbacks (all behaviour lives in the action functions).
  2. Transition table — a flat array of fsm_transition_t entries that fsm_run() scans linearly on every dispatched event.
Key design decision — EVT_SEG_ACK wired directly to act_send_window

An earlier version of the table routed EVT_SEG_ACK through an intermediate act_seg_ack action which simply dispatched EVT_START, which then triggered act_send_window. This two-hop approach was removed for two reasons:

  • It placed two events (EVT_SEG_ACK and EVT_START) into the FSM queue simultaneously, creating a brief window where the FSM had already consumed the ACK but not yet sent the next segment. A spurious second ACK arriving in that window could cause a double send.
  • It added unnecessary latency for every segment in the transfer.

The fix is simply:

{ &ST_SEND_WINDOW_STATE, EVT_SEG_ACK, &ST_SEND_WINDOW_STATE, act_send_window }

◆ fsm_table

fsm_transition_t fsm_table[]

Firmware update FSM transition table.

The firmware update FSM transition table.

Scanned linearly by fsm_run() on every dispatched event. The first row whose from pointer and event value match the current state and the event type is executed.

Reading the table
Each row is:
{ &FROM, EVENT, &TO, action_fn }

Rows are grouped by source state, happy-path first, error/retry paths immediately below.

Segment transmission state — the FSM spends most of its time here.

Segment-by-segment transmission state.

One CMD_PIPELINE_DATA packet is sent per entry. The state loops on itself driven by EVT_SEG_ACK (wired directly to act_send_window) until the current sector is exhausted, at which point EVT_SECTOR_END transitions to ST_VERIFY.

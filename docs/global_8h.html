◆ event_id_t

enum event_id_t

Event identifiers that drive transitions in the firmware update FSM.

Events are created with fsm_event_create() and dispatched via fsm_dispatch(). The act_fsm_signal_generation() function maps incoming protocol response codes to these event IDs.

Enumerator
EVT_START 

Generic start / proceed trigger.

Used in multiple states to kick off the next logical step:

  • In ST_INIT : begin the reset sequence.
  • In ST_BUILD_PIPELINE: begin the first segment send.
  • In ST_SEND_WINDOW : send the current (or next) segment.
  • In ST_NEXT_SECTOR : begin the next sector's first segment.
EVT_TARGET_INFO 

Target responded with bootloader and hardware parameters.

Triggered by RESP_TARGET_INFO. The associated event carries a heap-allocated copy of the received comm_packet_t in its data field.

EVT_SEG_ACK 

Target acknowledged receipt of the last segment.

Triggered by RESP_SEG_ACK. Causes the FSM to remain in ST_SEND_WINDOW and send the next segment.

EVT_SECTOR_END 

All segments of the current sector have been transmitted.

Dispatched internally by act_send_window() when pipeline_next_segment() signals there are no more segments. Transitions the FSM from ST_SEND_WINDOW to ST_VERIFY.

EVT_CRC_OK 

Target successfully wrote and verified the current sector.

Triggered by RESP_CRC_ACK. Advances the FSM to ST_NEXT_SECTOR.

EVT_CRC_NACK 

Target rejected the sector write (CRC mismatch or error).

Triggered by RESP_CRC_NACK. The act_crc_nack() handler resets the sector offset and retransmits the sector, up to the limit defined by MAX_RETRY.

EVT_ALL_SECTORS_DONE 

All sectors have been written to flash.

Dispatched internally by act_next_sector() when current_sector reaches pipeline.sector_count. Transitions the FSM from ST_NEXT_SECTOR to ST_APP_JUMP.

EVT_APP_ACK 

Target confirmed the application jump command.

Triggered by RESP_APP_JUMP_ACK. Transitions the FSM from ST_APP_JUMP to ST_DONE.

◆ state_id_t

enum state_id_t

Identifiers for each state in the firmware update FSM.

These values are stored in the id field of fsm_state_t and can be used for logging or runtime introspection. They must match the order in which the state objects are declared in fsm_table.c.

Enumerator
ST_INIT 

Idle state before the update procedure starts.

The FSM is placed here by fsm_init(). Waits for the first EVT_START from the application.

ST_SEND_RESET 

Reset request sent; waiting for target bootloader response.

The host has transmitted CMD_RESET_REQ and is waiting for the target to boot its bootloader and reply with RESP_TARGET_INFO.

ST_BUILD_PIPELINE 

Building the flash-sector pipeline from parsed HEX records.

pipeline_build() is called here to organise the firmware image into sector-aligned chunks ready for transmission.

ST_SEND_WINDOW 

Transmitting firmware segments and awaiting ACKs.

One CMD_PIPELINE_DATA packet is sent per entry of this state. The FSM loops here, driven by EVT_SEG_ACK, until the current sector is exhausted.

ST_VERIFY 

Sector CRC verification and flash write state.

A CMD_PIPELINE_VERIFY packet (carrying the sector CRC32) has been sent. The FSM waits for RESP_CRC_ACK or RESP_CRC_NACK from the target.

ST_NEXT_SECTOR 

Sector written successfully; advancing to the next sector.

Transfer cursors are updated here. The FSM either loops back to ST_SEND_WINDOW or transitions to ST_APP_JUMP when all sectors are done.

ST_APP_JUMP 

Application start command sent; waiting for jump ACK.

CMD_START_APP has been transmitted. The FSM waits here for RESP_APP_JUMP_ACK before declaring the update complete.

ST_DONE 

Terminal state — firmware update completed successfully.

fsm->fsm_running is cleared in this state, causing the main loop to exit.

queue_t handle_queue_receive_packets
extern

Receive packet queue shared between the communication thread and the FSM signal generator.

The comm_rx_thread pushes heap-allocated comm_packet_t pointers into this queue. act_fsm_signal_generation() pops and processes them on every main-loop iteration.

Detailed Description

Driver-independent packet framing for Serial, TCP, UDP, and CAN-over-Serial.

Supported frame formats

Serial / TCP / UDP — byte-stream framing with CRC16 integrity check:

┌─────┬─────┬───────┬───────┬──────────────┬───────┬───────┐
│ ':' │ CMD │ LEN_H │ LEN_L │ DATA[0..N-1] │ CRC_H │ CRC_L │
└─────┴─────┴───────┴───────┴──────────────┴───────┴───────┘
1 B 1 B 1 B 1 B N bytes 1 B 1 B

CRC16-CCITT computed over CMD + LEN_H + LEN_L + DATA.

UDP uses the identical frame layout as TCP. Each call to drv_udp_tx() sends one complete framed packet as a single datagram. drv_udp_rx() reads one datagram at a time; the byte-wise state machine then parses the bytes within that datagram in the same way as the Serial and TCP paths.

CAN-over-Serial — compact framing over the USB-CAN adapter virtual port:

┌─────┬─────┬─────┬──────────────────┐
│ ':' │ CMD │ LEN │ DATA[0..LEN-1] │
└─────┴─────┴─────┴──────────────────┘
1 B 1 B 1 B 0–8 bytes
Total: 3 + LEN bytes (max 11 bytes)

CAN frame field mapping from comm_packet_t:

  • pkt->command → CMD (= CAN ID, low 8 bits used as command code)
  • pkt->length → LEN (single byte, replaces LEN_H:LEN_L, max 8)
  • pkt->data[] → DATA (raw payload, no CRC appended)

The ':' delimiter is kept for easy re-synchronisation on the wire. No CRC bytes are appended — the CAN hardware provides a 15-bit CRC that the USB-CAN adapter validates before forwarding the frame.

Why no new CAN driver
The USB-CAN adapter exposes itself as a virtual serial port (ttyUSBx). The existing drv_serial_tx() / drv_serial_rx() calls are reused — only the byte packing inside transport_send() and transport_receive() differs from the Serial/TCP path.
